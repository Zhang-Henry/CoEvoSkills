# Flink Longest Session Per Job

This skill implements a Flink streaming job that:
1. Reads Google cluster trace task events and job events from gzipped CSV files
2. Filters task SUBMIT events (eventType=0)
3. Groups by jobId and applies EventTimeSessionWindows with a configurable gap (default 10 minutes)
4. Counts tasks per session window per job
5. Finds the session with the maximum task count per job
6. Only outputs results for jobs that have FINISH events (eventType=4)
7. Output format: `(jobId,maxTaskCount)` one per line

## Key Technical Details

### Data Schema (Google Cluster Trace)

**Task Events CSV columns:**
timestamp, missingInfo, jobId, taskIndex, machineId, eventType, user, schedulingClass, priority, cpuRequest, memoryRequest, diskSpaceRequest, differentMachinesRestriction

**Job Events CSV columns:**
timestamp, missingInfo, jobId, eventType, user, schedulingClass, jobName, logicalJobName

**Event Types:** 0=SUBMIT, 1=SCHEDULE, 2=EVICT, 3=FAIL, 4=FINISH, 5=KILL, 6=LOST, 7=UPDATE_PENDING, 8=UPDATE_RUNNING

### Timestamp Handling
- Dataset timestamps are in **microseconds**
- Flink event time uses **milliseconds**
- Convert: `event.timestamp / 1000`

### Session Window Strategy
- A "stage" is a period of SUBMIT events close together in event time
- Gap of 10 minutes (600 seconds) with no SUBMIT events ends a stage
- Uses `EventTimeSessionWindows.withGap(Time.seconds(600))`
- Each resubmission of a task counts separately

### Join Strategy
- Uses `KeyedCoProcessFunction` to join session counts with job finish events
- Registers event-time timer at `Long.MAX_VALUE - 1` to emit final results
- For bounded streams, this timer fires when the watermark reaches MAX_VALUE at stream end
- Only emits for jobs where both session counts AND finish event exist
